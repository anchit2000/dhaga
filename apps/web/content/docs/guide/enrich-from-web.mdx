Sometimes you want more context on a person than your own notes hold. The
**Enrich from public web ✦** button on a person's page fetches it — on demand,
never automatically.

![A person's profile with the amber Enrich from public web button and its caption explaining that findings are cited, saved as a note, and fully deletable](/docs/guide/person-facts-enrich.png)

## What it does

Press the button and Dhaga searches the public web for that person's footprint.
As the caption on the button says, it *"searches the public web for their
footprint — cited, saved as a note, fully deletable."* Concretely:

1. Findings come back **cited** — every claim links to where it was found.
2. They're saved as a **normal note** on the person, just like one you'd write
   yourself.
3. That note can, in turn, yield **facts** (each with its receipt).
4. You can **delete** the note — and its derived facts tombstone with it — at
   any time.

The search plus extraction takes 20–60 seconds and runs **in the background**:
the progress pill above the Facts section tracks it, it keeps running if you
leave the page, and it finishes with a short confirmation of what was added. Go
elsewhere in the meantime and the result finds you through the
[**bell**](/docs/guide/calendar#staying-reminded) in the top nav — including when
it turns up nothing, or fails.

Enrichment is a **Pro-and-up feature**, and the most expensive action in Dhaga
at **20 [credits](/docs/guide/ai-credits)** — it pays for live web searches on
top of the model. A free account's monthly allowance doesn't stretch to one, and
wouldn't unlock the button even if it did.

## Privacy

Enrichment is **always user-triggered**. Dhaga never reaches out to the public
web about a contact on its own or in the background — you press the button, for
one person, each time. That keeps enrichment consistent with the rest of the
product: no silent data collection.

<Callout title="Requires an AI provider that can search the web">
Enrichment asks the *LLM* provider to run its own web search, so all it needs is
`ANTHROPIC_API_KEY` (or another provider declaring the `webSearch` capability).
**Corrected 2026-08-08:** this note used to say enrichment needed
`SEARCH_PROVIDER` set. It does not — `SEARCH_PROVIDER` selects the search gateway
used by the nightly job-change/news sweep, which is a separate path. See
[Add a search provider](/docs/extending/search-provider) for that one.
</Callout>
